# Описание дипломной работы

Темой выпускной квалификационной работы является разработка интеллектуального приложения AI Data Engineer Assistant, предназначенного для автоматизации и поддержки задач data engineering. Актуальность темы обусловлена ростом объёмов данных, усложнением аналитической инфраструктуры и необходимостью ускорять работу специалистов, которые ежедневно взаимодействуют с базами данных, пайплайнами, Airflow DAG, Spark-задачами и инструментами мониторинга. В современных компаниях data engineer должен не только писать SQL-запросы и поддерживать процессы обработки данных, но и быстро анализировать сбои, запускать вычисления, проверять статусы заданий и документировать изменения. Поэтому востребованы интеллектуальные системы, которые объединяют рабочие инструменты в едином интерфейсе.

В рамках работы был рассмотрен полный жизненный цикл разработки цифрового продукта для инженерной работы с данными. На начальном этапе проведён анализ предметной области: изучены типовые задачи data engineering, сценарии эксплуатации хранилищ данных, особенности работы с оркестраторами пайплайнов, распределёнными вычислениями и инструментами отладки. Также был выполнен анализ существующих решений, включая интерфейсы управления Airflow, Spark UI, SQL-редакторы и ассистенты на основе языковых моделей. Это позволило определить ограничения разрозненных инструментов и сформулировать требования к единой системе, в которой пользователь может задавать цель естественным языком, а приложение выбирает необходимые действия.

Особое внимание в проекте уделено агентской архитектуре. Интеллектуальная составляющая реализована через агентские циклы, включающие анализ запроса пользователя, определение намерения, выбор подходящего инструмента, выполнение действия, проверку результата и формирование ответа. Такой цикл позволяет ассистенту работать не как справочная система, а как активный участник процесса data engineering. Например, пользователь может попросить проанализировать таблицу заказов за последние дни, после чего агент классифицирует задачу как SQL-сценарий, формирует безопасный read-only запрос, выполняет его, анализирует результат и возвращает понятное объяснение. При работе с Airflow агент может открыть нужный экран, показать список DAG, остановить или возобновить пайплайны, запустить DAG и проверить статус выполнения. Для Spark-задач агент способен отправлять job, отслеживать её состояние и показывать фрагмент результата.

Важной особенностью системы является использование инструментов, близких по возможностям к действиям человека в интерфейсе. Для этого реализованы function tools и MCP-совместимое описание инструментов по продуктовым областям: база данных, Airflow, Spark, артефакты. Такой подход позволяет агенту не подменять реальные действия текстовыми ответами, а вызывать конкретные операции: выполнять SQL, просматривать каталог таблиц, инспектировать содержимое базы, управлять DAG, запускать вычисления, сохранять скрипты и проверять их в изолированной среде. При этом каждое действие фиксируется как tool call, что повышает прозрачность работы системы.

Практическая часть работы включает фулстек-разработку приложения. Интерфейс включает экраны AI Agent, SQL Workspace, Pipelines, Airflow, Spark, Catalog, Connections, Settings и Profile. Серверная часть построена на FastAPI и отвечает за авторизацию, хранение пользователей, историю сессий, сообщения, tool runs, метаданные пайплайнов и Spark-задач. Агентская логика организована с использованием LangGraph, что позволяет явно описать этапы выполнения: выбор runtime, обращение к модели, выполнение инструментов, локальный fallback и финализацию ответа.

Отдельное внимание уделено безопасности и воспроизводимости. SQL-инструмент ограничен read-only запросами, пользовательские артефакты сохраняются раздельно по пользователям, а обычный пользователь видит только свои версии. Для DAG и Spark-скриптов реализована запись файлов, синтаксическая проверка, Git-версионирование и запуск в Docker sandbox. Изолированная среда позволяет агенту не только писать код, но и отлаживать его: запускать проверку DAG, выполнять Spark-скрипты, анализировать ошибки и возвращать рекомендации. Такой механизм снижает риск повреждения основной системы и делает эксперименты с кодом управляемыми.

Результатом выпускной квалификационной работы стало функционирующее интеллектуальное приложение, демонстрирующее возможность объединения агентского подхода, MCP-инструментов, SQL-аналитики, управления Airflow и Spark-задачами в единой рабочей среде data engineer. Разработанное решение имеет потенциал для дальнейшего развития: подключения реальных корпоративных источников данных, расширения набора инструментов, внедрения дополнительных ролей доступа и интеграции с промышленными контурами наблюдаемости. Таким образом, выполненная работа сочетает исследовательскую и практическую составляющие, отражая навыки анализа предметной области, проектирования архитектуры, реализации фулстек-приложения и создания агентских систем для инженерии данных.
